## 判定与边界

- 原始评测器要求模型新增测试文件而不能改原文件，直接 Pi 正常追加旧测试时被拒绝。因此该严格结果包含规则遵守，不等同于功能正确性，也不能直接当作两组业务成功率。
- 统一复核不修改模型生产代码，暂时恢复基线原测试快照，保留新增测试文件，执行全仓检查、API/Worker 构建和外置验收，然后恢复模型提交的测试。原版测试快照不能被模型削弱。
- NewAgent 因审查 JSON 枚举错误而阻塞时，功能即使正确也不是完整交付成功；两种结果均保留。
- 试验耗时包含各方案自己的检查与工具执行；严格规则提前中断时缺少原计划后验检查，因此不直接计算速度提升。统一复核耗时单列。
- WSL 环境不一致的首个试运行已排除并保留 excluded-pilot.json；其临时 Node 下载已清理。正式六次试验使用 Git Bash、Windows Node 22.23.3。
- 正式试验没有人工修正模型代码；环境配置和评测规则的解释有人工介入，不能宣称全流程零人工。
- 每组仅3个不同任务、每项只运行一次，不能推断总体成功率、P95、显著性、人效提升或审查精确率/召回率。
- 费用未配置，真实账单未取得；零 SDK cost 不等于免费。
- API/Worker 的外部数据库集成用例有跳过，本轮不是生产环境验证。

证据：results.json 保存原始结果和模型 usage；audited-results.json 保存统一复核；各任务日志与代码副本可复查。
